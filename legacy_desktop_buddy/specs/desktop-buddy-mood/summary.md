# 情绪与状态系统完成总结（desktop-buddy-mood）

## 交付结果

好感度 + 精力 → 心情 → 同时调制动作、语录、对话三层。22 项逻辑用例全部通过，已打包安装运行。

## 状态模型

**好感度**落盘，0-100，初始 20。点击 +1、对话 +2、完成 todo +3，**每日上限 +15**；每满 24 小时不互动 −5，下限 0。

**精力不落盘**，按当前小时派生（凌晨 15、上午 10-11 点 90、午后 55、傍晚 85、深夜 30）。精力本质是时间函数，存下来反而要处理"存的值和现在时间不一致"的问题。

**心情**按优先级派生：困意 → 孤单（3 天未互动）→ 生分（好感 <30）→ 开心（≥70）→ 平静。

## 三个关键决策

**每日累积上限**。不设上限的话连点二十下就能刷满，好感度立刻失去意义。实测连点 30 次当天只从 20 涨到 35。

**衰减用"记录时间点 + 读取时结算"，不用定时器**。和备忘录弹窗同源的判断：macOS 睡眠唤醒后长定时器不可靠。同时防了系统时钟回退——`lastSeenAt` 落在未来时不衰减，只把它修正回当前时间。

**情绪只有 60% 概率替换语录**。性格是产品核心，情绪只是调味；全部替换会让用户觉得"我写的性格没生效"。同理，对话的状态注入里明确写了"不要卖惨、不要强行活跃"——状态注入很容易让模型进入戏剧化表演，那让人尴尬而不是觉得可爱。

## 三层调制的实测效果

| 层 | 效果 |
|---|---|
| 动作幅度 | 精力低时元气角色的动作池从 6 个收缩到只剩摇摆/歪头/点头；低落时去掉打滚和转圈 |
| 动作频率 | 标准性格：困 88 秒 / 平常 41 秒 / 开心 31 秒一次；倍率与性格叠乘后，高冷角色在深夜约 160 秒才动一次 |
| 呼吸 | 通过 CSS 变量从 1.8 秒放慢到 3 秒，视觉上就是"没精神" |
| 语录 | 困/孤单/开心各 10 条专属台词，60% 概率命中 |
| 对话 | system prompt 追加状态行，四档文案各有行为约束 |
| 主动性 | 深夜完全不主动搭话 |

## 验证（22 项全过）

时段映射 4 项、心情派生优先级 5 项、衰减 4 项（满天扣、不满不扣、下限、时钟回退）、防刷 3 项（连点上限、跨天恢复、三种行为分值）、动作调制 6 项（池收缩、低落过滤、频率倍率、性格与情绪倍率相乘、呼吸时长）。

其中"性格倍率与情绪倍率相乘"这项确认了设计意图：情绪不是覆盖性格，而是叠加在性格之上——高冷角色即使心情好也不会变得像元气角色那样活跃。

## 边界处理

系统时钟回退不扣分、长期不用衰减到 0 不出现负值、好感满 100 不再累积、情绪池缺失时回落性格池不出现空气泡、取消勾选 todo 不加分（避免反复勾选刷分）、首次读取时 `lastSeenAt` 为 0 会用当前时间初始化（否则会被算成几十年没互动）。
