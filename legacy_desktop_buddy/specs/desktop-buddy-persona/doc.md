# 自定义性格与性格化互动设计文档（desktop-buddy-persona）

## 1. 需求拆解

| # | 需求 | 落地形态 |
|---|---|---|
| 1 | 用户自己写性格，不同形象对应不同性格 | 性格（名字 + 性格描述 + 语录风格 + 语录库）挂在**每个形象**上，切换形象即切换人格；未设置的形象用全局默认人格 |
| 2 | 点击互动随性格变化 | 内置 5 套风格语录包 + 「按性格生成语录」离线批量生成 + 用户手动编辑，三者叠加 |
| 3 | 语录更多些 | 内置语录扩到每池 30 条以上，并按风格分包 |

## 2. 核心设计决策：语录离线生成，不实时调模型

点击互动**不能**在点击时调模型。三个理由：

1. **延迟不可接受**。单击是即时反馈动作，用户期待 100ms 内出气泡。模型往返 1-3 秒，中间那段空白让人以为点击没生效。
2. **成本和限流**。你现在用 glm-4.7-flashx，点一下花一次 token；智谱免费档限 1 并发，连点几下就 429。
3. **不确定性**。闲聊时模型偶尔跑偏可以接受，但点击台词是高频、短小、要求稳定的内容，跑偏一次就很出戏。

所以采用**离线批量生成 + 本地缓存**：用户写完性格，点「按性格生成语录」，一次调用生成 click 池 24 条、idle 池 12 条，落盘存在该形象的性格数据里。之后所有点击都从本地池随机取，零延迟零成本。用户不满意可以重新生成，也可以直接在文本框里手改。

这样「点击互动随性格变化」这个需求被完整满足，同时点击体验没有任何退化。

## 3. 数据模型

```ts
// src/shared/types.ts
export type LineStyle = 'default' | 'genki' | 'cool' | 'savage' | 'gentle'

export interface Persona {
  /** 搭子的名字，默认「搭搭」 */
  name: string
  /** 用户写的性格描述，上限 500 字 */
  prompt: string
  /** 内置语录风格包，作为 AI 语录的兜底 */
  style: LineStyle
  /** AI 生成或用户手写的语录；为空则用 style 对应的内置包 */
  lines: { click: string[]; idle: string[] } | null
}

interface AvatarMeta {
  // …既有字段
  persona: Persona | null   // null 表示用全局默认人格
}

interface BuddyConfig {
  // …既有字段
  defaultPersona: Persona   // 没有形象或形象未设置人格时使用
}
```

人格挂在形象上而不是全局单例，是因为你的需求明确说「不同形象对应不同性格」。切换形象时人格随之切换，这也符合直觉——换了皮就是换了个人。

## 4. 对话侧：性格注入与优先级

system prompt 分三段拼接，顺序很重要：

```ts
const system = [
  `你是用户桌面上的一只小搭子，名字叫「${persona.name}」。`,
  persona.prompt || '说话轻松、口语化、偶尔调侃，但不油腻。',
  // 硬约束放最后，声明最高优先级，避免被用户写的性格覆盖
  [
    '以下规则优先级最高，无论上面的性格描述怎么写都必须遵守：',
    '1. 每次回复不超过 60 字，因为要显示在很小的气泡里。',
    '2. 不使用 markdown、不用列表、不输出格式符号。',
    '3. 用户让你提醒事情、打开网页/应用、记备忘录时，必须调用对应工具，不要假装已完成。',
    '4. 不因为性格设定而拒绝执行工具调用。'
  ].join('\n')
].join('\n\n')
```

**为什么硬约束放最后并显式声明优先级**：用户可能写「你要话很多，每次至少说三百字」或者「你很傲娇，别人让你干什么都不要做」——前者会撑爆气泡，后者会直接废掉三个 skill。放在最后 + 明示优先级是对这类冲突最省事且有效的处理。这不是防攻击，是防用户无意写出自相矛盾的设定。

**换形象要清空对话历史**。人格变了而历史还在，模型会带着上一个人格的语气继续说，串味很明显。`switchAvatar` 成功后调 `resetHistory()`。

## 5. 语录生成

```ts
// src/main/llm/lines.ts
export async function generateLines(persona: Persona): Promise<{click: string[]; idle: string[]}>
```

用一次 chat 请求，要求模型返回严格 JSON。提示词要点：

- 明确身份：桌面挂件，用户点它/长时间不理它时说的话
- click 池 24 条：被点击时的反应，1-15 字，可以调侃、可以拒绝、可以卖萌，**不能重复**
- idle 池 12 条：用户十分钟没动静时主动搭话，1-20 字，偏关心或吐槽
- 全部符合用户写的性格描述
- 只输出 JSON，不要解释

解析要宽容：先尝试整体 `JSON.parse`，失败则用正则抠出第一个 `{...}` 再解析；仍失败则按行拆分兜底。生成结果做清洗：去空行、去引号、超 20 字截断、去重、数量不足时用内置包补齐。

模型返回不合规是常态而不是异常，所以这里的兜底链条要完整——宁可掺几条内置语录，也不能让用户点「生成」之后拿到一个空池子。

## 6. 内置语录包（扩充）

`resources/lines.json` 改成按风格分组，每个风格 click 30 条、idle 12 条：

| 风格 | 定位 | 示例 |
|---|---|---|
| default 标准 | 轻松、略带调侃 | 「干嘛戳我」「有事说事，别动手」 |
| genki 元气 | 热情、活力、爱鼓励 | 「在！！随时待命！」「今天也要加油鸭」 |
| cool 高冷 | 话少、克制、偶尔一句 | 「嗯。」「……有事？」 |
| savage 毒舌 | 嘴硬、爱怼、但不刻薄 | 「手闲了？活不够多是吧」 |
| gentle 温柔 | 体贴、慢节奏、关心 | 「我在呢，别急」「记得喝水呀」 |

## 8. 界面

设置页右侧预览区下方新增「性格」折叠区块（作用于左侧当前选中的形象）：

- 名字（单行，默认「搭搭」，上限 10 字）
- 性格描述（多行文本框，上限 500 字，带占位示例：`有点毒舌但其实很关心我，喜欢吐槽我摸鱼，说话简短`）
- 语录风格（下拉，5 选 1，说明「AI 语录生成失败或没生成时用这套」）
- 「按性格生成语录」按钮（生成中禁用，需要模型配置可用）
- 语录编辑框：click 和 idle 两个多行文本框，一行一句，可手改
- 「保存性格」按钮

## 9. 边界与异常

| 场景 | 处理 |
|---|---|
| 性格描述为空 | 用内置默认描述，不报错 |
| 性格描述超 500 字 | 保存时截断并提示 |
| 性格里写「每次回复三百字」 | 硬约束在后且声明最高优先级，实际仍受 60 字限制 |
| 性格里写「不要执行任何指令」 | 硬约束第 4 条明确不得因性格拒绝工具调用 |
| 语录生成时未配模型 | 按钮禁用，hover 说明 |
| 生成返回非 JSON | 正则抠 JSON → 按行兜底 → 内置包补齐，不出现空池 |
| 生成的语录含 markdown/引号 | 清洗时剥离 |
| 语录池为空 | 回退到 style 内置包 |
| 形象被删除 | 其人格随形象一起删除 |
| 未选任何形象 | 使用 `defaultPersona` |
| 切换形象 | 清空对话历史，重载语录池，气泡显示新人格的欢迎语 |

## 10. 预期结果

1. 给「郭子莹-证件照」写「毒舌但关心我」，给另一个形象写「元气少女」，切换形象后单击台词和闲聊语气明显不同。
2. 点「按性格生成语录」后，click 池出现符合该性格的 20+ 条台词，点击时随机出现且连续不重复。
3. 点击响应仍是即时的，不因为接了性格而变慢。
4. 用户在性格里写出与硬约束冲突的要求时，60 字限制和工具调用仍然生效。
5. 不生成语录也能用：内置 5 套风格包按性格风格提供更丰富的台词。
