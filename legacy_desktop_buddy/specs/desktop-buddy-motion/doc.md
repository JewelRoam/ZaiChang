# 桌宠动作系统设计文档（desktop-buddy-motion）

## 0. 先说清一个限制

你的形象是**任意上传的单张静态图**，没有分层、没有骨骼、没有多帧素材。这决定了「动作」能做到什么程度：

- **能做**：整体变换类动作——跳、蹲、晃、转身、打滚、抖、缩放、倾斜；以及窗口级位移——在桌面上溜达几步再回来。这类动作零素材成本，对任何图都生效。
- **做不到**（除非补素材）：抬手、眨眼、张嘴、走路时腿在动。这些需要角色分层或多帧图，单张图变换不出来。
- **有第三条路**：用已经打通的百炼图像编辑，从原图生成几张**姿态图**（挥手、闭眼睡觉、比耶、瘫倒），动作时切换姿态图 + 叠加变换。这是「真动作」的可行路径，一张 0.2 元，一次性投入。

本方案把前两类做成默认能力（立刻可用），姿态图做成可选增强。我不建议一上来就做姿态图：先看变换类动作的效果够不够，很多桌宠的生动感其实来自节奏和随机性，而不是帧数。

## 1. 需求拆解

| # | 需求 | 落地 |
|---|---|---|
| 1 | 不点击时也会偶尔自己做动作 | 自发动作调度器：默认每 20-60 秒随机触发一个动作，频率可配（低/中/高/关） |
| 2 | 点击时触发动作 | 单击从动作池随机取一个，替代现在固定的摇晃 |
| 3 | 动作和性格挂钩 | 每种性格有自己的动作偏好池（元气爱跳、高冷只轻微晃、毒舌抖动翻脸） |

## 2. 动作库（L1 变换类，零素材）

全部用 CSS `transform` + `@keyframes` 实现，不引动画库。

| 动作 | 效果 | 时长 |
|---|---|---|
| `jump` | 向上跳并轻微压扁落地 | 600ms |
| `hop` | 连续两下小跳 | 800ms |
| `sway` | 左右缓慢摆动身体 | 1200ms |
| `shiver` | 高频小幅抖动（受惊/冷） | 500ms |
| `spin` | 原地转一圈（Y 轴翻转，像转身） | 700ms |
| `roll` | 整体旋转 360°（打滚） | 900ms |
| `squash` | 下蹲压扁再弹回 | 500ms |
| `tilt` | 头歪一边（好奇） | 900ms |
| `stretch` | 拉长伸懒腰 | 1100ms |
| `pop` | 快速放大再回弹（惊讶） | 400ms |
| `nod` | 上下点头两次 | 700ms |
| `wobble` | 果冻式左右形变 | 800ms |

配合 `transform-origin: 50% 90%`（脚底），跳和蹲才有重量感——这一条是效果好坏的关键，原点放中心会显得在飘。

## 3. 动作库（L2 窗口位移类）

| 动作 | 效果 | 说明 |
|---|---|---|
| `stroll` | 沿屏幕水平走一段（120-260px）再走回来 | 主进程分帧移动窗口，60ms 一帧，配合 `sway` 让它像在走 |
| `peek` | 贴着屏幕边缘缩进去一半再冒出来 | 只在靠近屏幕边缘时触发 |

位移动作**默认关闭**，设置里可开。理由：会移动窗口位置，有人会觉得被打扰或找不到搭子。开启时也做两条约束——走动范围不超出当前屏幕工作区，结束后回到原位并持久化，避免越走越偏。

## 4. 性格化动作偏好

```ts
const MOTION_BY_STYLE: Record<LineStyle, MotionName[]> = {
  default: ['jump', 'sway', 'nod', 'tilt', 'wobble', 'squash'],
  genki:   ['hop', 'jump', 'spin', 'pop', 'roll', 'wobble'],   // 幅度大、频率高
  cool:    ['sway', 'tilt', 'nod'],                             // 只做小动作
  savage:  ['shiver', 'wobble', 'spin', 'squash', 'pop'],
  gentle:  ['sway', 'stretch', 'nod', 'tilt']                   // 慢、柔
}
```

自发动作的间隔也随性格浮动：`genki` 偏短（15-40s），`cool` 偏长（45-120s），其余取中间。这比所有性格用同一个节奏更像"不同的人"。

## 5. 调度设计

**自发动作**独立于现有的「空闲 10 分钟主动搭话」。两者是不同的东西：动作高频无文字，搭话低频有气泡。

```ts
// 频率档位 → 间隔区间（毫秒）
const INTERVAL: Record<MotionFreq, [number, number]> = {
  off:    [0, 0],
  low:    [60_000, 150_000],
  normal: [20_000, 60_000],
  high:   [8_000, 25_000]
}
```

触发前的三道闸门，缺一个都会变成骚扰：

1. 当前动画状态必须是 `idle`（正在说话/思考/执行其他动作时不打断）
2. 对话面板打开时不做动作（用户在专注输入）
3. 窗口不可见时不做动作，且**暂停呼吸动画**

第 3 条不只是礼貌问题，是耗电问题：CSS 动画在后台持续跑会一直占 GPU 合成，对笔记本电池不友好。用 `document.visibilitychange` + 窗口 `hide/show` 事件处理。

**点击动作**：从当前性格的动作池随机取，连续两次不重复（和台词一样的去重逻辑）。台词和动作同时出，形成"点一下 → 它跳一下 + 说句话"的完整反馈。

## 6. 数据模型

```ts
export type MotionName = 'jump' | 'hop' | 'sway' | 'shiver' | 'spin' | 'roll'
  | 'squash' | 'tilt' | 'stretch' | 'pop' | 'nod' | 'wobble' | 'stroll' | 'peek'

export type MotionFreq = 'off' | 'low' | 'normal' | 'high'

export interface MotionConfig {
  freq: MotionFreq        // 默认 'normal'
  allowMove: boolean      // 是否允许 stroll/peek 这类移动窗口的动作，默认 false
}
```

放在 `BuddyConfig` 里作为全局设置（不挂形象）。动作偏好由性格的 `style` 推导，不额外增加用户要填的东西——性格已经要写描述和选风格了，再让用户勾 12 个动作就太啰嗦。

## 8. 边界与异常

| 场景 | 处理 |
|---|---|
| 动作播放中又被点击 | 忽略新动作，不打断（避免抽搐感） |
| 正在 thinking/talking | 自发动作跳过这一轮，不排队 |
| 对话面板打开 | 不做自发动作 |
| 窗口隐藏 / 系统休眠唤醒 | 暂停动画与调度，恢复后重新计时（不补做） |
| 全屏应用下 | 窗口本身已自动隐藏，调度随之停止 |
| `stroll` 走出屏幕 | 目标位置先 clamp 到工作区内，再分帧移动 |
| `stroll` 中用户拖拽 | 拖拽事件优先，立即停止走动并以当前位置为新原点 |
| 多显示器 | 走动只在当前所在屏幕的工作区内 |
| 频率设为 off | 只保留呼吸和点击动作，不做自发动作 |
| 性格切换 | 动作池随之切换，正在播的动作不中断 |

## 9. 预期结果

1. 不碰它时，平均半分钟左右会自己跳一下、晃一下、伸个懒腰，动作随机不重复。
2. 单击时立刻出现动作 + 台词，动作符合当前性格（元气爱跳、高冷只轻微晃）。
3. 频率可调，设为「关」后只剩呼吸。
4. 开启「允许走动」后偶尔会在桌面上溜达一小段并走回来，不会跑出屏幕、不会越走越偏。
5. 搭子隐藏或进入全屏应用时，动画和调度都停下来，不空耗电量。
6. 说话、思考、面板打开时不会被自发动作打断。

## 10. 后续可选（本次不做）

用百炼图像编辑从原图生成 4-6 张姿态图（挥手、闭眼、比耶、瘫倒），动作时切图 + 叠加 L1 变换。成本约 1 元一次性，能把「整体在动」升级成「角色在做具体动作」。等你看过 L1 的实际效果再决定值不值。
