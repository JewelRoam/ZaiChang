# 自定义性格与性格化互动完成总结（desktop-buddy-persona）

## 交付结果

性格挂在每个形象上，换形象即换人格；点击语录随性格变化且保持零延迟。已打包安装，用你的真实智谱 key 验证通过。

## 关键设计与理由

**语录离线生成，不实时调模型**。这是本次最重要的取舍。点击是即时反馈动作，走网络会有 1-3 秒空白、每点一次花钱、免费档还会撞并发限制。做法是「按性格生成语录」一次批量生成 24 条点击 + 12 条空闲存本地，之后点击从本地池随机取。需求「点击互动随性格变化」被完整满足，点击体验没有任何退化。

**三段式 system prompt，硬约束放最后**。顺序是身份 → 用户写的性格 → 硬约束（60 字上限、不用 markdown、必须调用工具、不得因性格拒绝执行），并显式声明硬约束优先级最高。这不是防攻击，是防用户无意写出自相矛盾的设定——「每次回复三百字」会撑爆气泡，「什么都别做」会直接废掉三个 skill。

**换形象和改性格都清空对话历史**。人格换了而历史还在，模型会带着上一个语气继续说，串味很明显。

**人格挂形象而非全局**，因为需求明确说「不同形象对应不同性格」。未设置人格的形象回落到全局默认人格。

**生成结果层层兜底**。整体 JSON → 正则抠 JSON → 按行拆分；再做清洗（去编号、去引号、去 markdown、超 20 字截断、去重）；数量不足用内置风格包补齐并告知用户「部分是内置补的」。模型返回不合规是常态，不能让用户点完生成拿到空池子。

**内置语录扩到 5 套风格 × 42 条**（标准/元气/高冷/毒舌/温柔），每套 30 条点击 + 12 条空闲，已校验无重复。不生成 AI 语录也比原来丰富得多。

**循环依赖处理**：`client.ts` 需要读人格，`manager.ts` 需要在改人格后清历史，两者会形成 import 环。把人格解析下沉到 `store.ts`，两边都只依赖 store，环解开。

## 真实模型验证（6 项全过）

| 项 | 结果 |
|---|---|
| 不同性格语气不同 | 毒舌「也就是我，换个人早被开除了。」/ 温柔「没关系的呀，偶尔摸鱼也是一种充电方式…」 |
| 毒舌回复 ≤60 字 | 14 字 |
| 温柔回复 ≤60 字 | 32 字 |
| 冲突性格（要求三百字）下仍守字数 | 实际 3 字 |
| 冲突性格（要求拒绝执行）下仍调用工具 | 成功调用 `set_reminder` |
| 按性格生成语录可解析 | click 24 条 / idle 12 条，样例：「手别抖，它就两下」「正事不做，在这儿玩」 |

最后一项证明了硬约束设计是有效的：模型在被明确要求「拒绝调用任何工具」的性格设定下，仍然执行了工具调用。

## 用法

设置页选中形象 → 下方「性格」区块 → 填名字和性格描述 → 选语录风格 → 点「按性格生成语录」→ 检查生成结果（可手改，一行一句）→ 点「保存性格」。
