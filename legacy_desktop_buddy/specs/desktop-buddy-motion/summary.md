# 桌宠动作系统完成总结（desktop-buddy-motion）

## 交付结果

14 个动作（12 个变换 + 2 个走动），点击触发 + 自发触发，节奏和幅度跟性格绑定。已打包安装并运行。

## 能力边界（先说清楚）

形象是单张静态图，没有分层和多帧，所以动作只能是**整体变换**：跳、连跳、摇摆、发抖、转身、打滚、下蹲、歪头、伸懒腰、惊讶弹跳、点头、果冻晃。抬手、眨眼、张嘴这类做不到——那需要角色分层或姿态素材。

想要真动作的路径是用百炼图像编辑生成几张姿态图（挥手、闭眼、比耶），动作时切图叠加变换，一张 0.2 元。本次没做，建议先看变换动作的实际效果——桌宠的生动感很大程度来自节奏和随机性，不一定需要帧数。

## 关键设计

**transform-origin 放脚底（50% 90%）**。跳和蹲的重量感全靠这个，原点放中心会显得在飘。

**性格决定动作池和节奏**，用户不用额外勾选动作。元气用大幅动作（跳/转/打滚）且间隔缩短到 0.6 倍，高冷只有摇摆/歪头/点头且间隔拉长到 1.8 倍。实测平均间隔：元气 24 秒，高冷 72 秒。

**自发动作与「空闲主动搭话」是两套机制**。动作高频无文字（20-60 秒），搭话低频有气泡（10 分钟）。混在一起会让搭子既吵又呆。

**三道闸门**：状态必须是 idle（不打断说话/思考/其他动作，也不排队）、对话面板打开时不动、窗口不可见时不动并**暂停呼吸动画**。最后一条不只是礼貌——CSS 动画在后台持续跑会一直占 GPU 合成，对笔记本电池不友好。

**走动默认关闭**。它会移动窗口位置，有人会觉得被打扰或找不到搭子。开启后目标位置先 clamp 到当前屏幕工作区，走完回原位并持久化（避免越走越偏），用户一拖拽立即中止并以当前位置为新原点。

## 验证（10 项全过）

| 项 | 结果 |
|---|---|
| 动作数量 | 14 个 |
| 每个动作都有对应 CSS 类 | 全部存在 |
| CSS 动画时长与代码时长表一致 | 全部一致（含 hop 这类靠 repeat 累计时长的） |
| 关闭走动时池内无 stroll/peek | 通过 |
| 开启走动时池内含 stroll/peek | 通过 |
| 连续 300 次抽取无重复 | 重复 0 次 |
| 高冷性格不出现大幅动作 | 池内仅 sway/tilt/nod |
| 频率设为「关」返回 0 | 通过 |
| high < normal < low | 17s < 39s < 103s |
| 元气比高冷动得频繁 | 24s vs 72s |

其中「CSS 时长与代码时长表一致」这项值得单列：动作时长在 CSS 和 TS 里各写了一份，不一致会导致动画还没播完状态就回落（动作被截断）或播完了状态还卡着（下个动作被吞）。这是双份真相必然产生的问题，用测试锁住比靠记性可靠。

## 用法

设置页「互动」区块：动作频率（关/低/正常/高）、允许在桌面上走动。改完即时生效，不用重启。
