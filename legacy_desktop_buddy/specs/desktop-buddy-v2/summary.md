# 桌面搭子 v2 完成总结

## 你那条对话用不了的原因

不是 key 的问题：`baseUrl` 和 `model` 两项都是空的，代码里三项缺一就会拒绝发请求。**那个 key 已经出现在对话记录里了，请去服务商后台吊销换一个**，新 key 直接填进设置页。填完点新增的「测试连接」按钮，它会明确告诉你是地址不通、401、模型名不对、还是模型不支持 function calling。

## 四条需求的落地

**抠图**：新增 `matting.ts`，支持 rembg 风格（multipart 上传直接返回 PNG）和 OpenAI 兼容（`/images/edits`）两种协议，设置页可选。抠图成功后自动用抠图结果重做本地 Q 版，并默认启用；可以取消勾选「使用抠图结果」退回原图。关键防御是**校验结果是否真有透明像素**——中转服务把请求转给不支持抠图的模型然后原样回吐原图是常见失败模式，不校验的话你看到的是「成功但没变化」。

**换形象交互**：设置页改成左侧形象库 + 右侧大图预览。点缩略图和切形态只改预览，点「应用到桌面」才生效，与当前一致时按钮禁用并显示「已是当前形象」。历史形象都留着，标注「使用中 / 已抠图 / AI Q 版」三种状态。

**备忘录**：新增独立窗口 + `memo.json` 独立存储（不和形象、模型配置混在一个文件里，避免勾选 todo 这种高频写入连带损坏配置）。默认 9:00 弹出，用「每分钟轮询 + 当日标记」而不是长定时器——macOS 睡眠唤醒后长定时器不可靠，睡过头就永远不弹了。昨日未完成自动带过来并标记原条目（防止同一件事每天复制越滚越多），单条可设提醒时间，启动时重建当天未过期的提醒。另外加了 `add_todo` / `list_todos` 两个 skill，直接跟搭子说「记一下…」就能写进同一个备忘录。

**真 Q 版**：源图优先用抠图结果（背景干净对 Q 版化效果影响很大），prompt 明确了头身比、保留发色服装、透明背景、无水印，失败时把接口返回的具体报文透传到界面，已有产物时按钮变「重新生成」并二次确认。

## 验证结果

- `tsc --noEmit`、`electron-vite build`、`electron-builder` 打包全部通过，`memo.html` 正确进入 asar。
- 三个窗口（搭子 / 设置 / 备忘录）实际启动均正常渲染，无控制台报错。
- 备忘录数据层 7 组用例通过：空文本拒绝、超长截断到 200、完成项排序靠后、删除、昨日未完成只带一次且不重复复制、启动重建只取未来提醒、`memo.json` 损坏时备份并以空列表启动。
- 抠图 4 组用例通过（用本地假服务器）：接口回吐不透明图被判失败、透明 PNG 正常落盘、JSON 包装的 base64 能取出、401 报鉴权失败。base64 提取加了魔数校验，避免把长 token 当成图片数据。
- 连接诊断 7 组用例通过：缺配置、地址非法、连不上、401、模型不存在、不支持 tools（能对话但明确告知 skill 会失效）、全部正常。
- 验证用的临时测试文件和 release 产物已清理；今日的备忘弹窗标记也已重置，你运行时能看到弹窗。

## 还卡在你这边的三件事

1. **`baseUrl` + 模型名**：对话和 AI Q 版都等这个。中转服务的地址我不该猜。
2. **抠图服务地址**：接口已经做成可配置的，两种协议都实现了，但没有地址就用不了。如果没有现成的，可以自建 rembg 或找个在线抠图 API。
3. **AI Q 版的实际可用性**：很多中转只代理 `chat/completions`，不一定支持 `images/edits`。拿到地址实测后如果不支持，需要换成 `images/generations` 形态或另找图像服务——我没有预先写两套适配，避免为假设做设计。

apiKey 仍然是明文存本地，这一点没变，仍是有意取舍。
