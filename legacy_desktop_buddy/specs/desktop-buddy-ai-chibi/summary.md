# AI 生成真 Q 版完成总结（desktop-buddy-ai-chibi）

## 交付结果

百炼 DashScope 图像编辑链路已打通，用你的真实 key 跑过完整一遍：**原图 → 生成 Q 版（7.5 秒，1024×1024，809KB）→ 自动抠图去底（alpha 最小值 0）**。生成的样品已放在你桌面：`搭子Q版预览.png`。

## 做了什么

**协议适配**。百炼的图像接口不支持 OpenAI 兼容模式，请求体是 `input.messages` 里塞 `{"image":...}` 和 `{"text":...}`，返回的是 24 小时过期的 OSS 临时 URL。新增 DashScope 分支，拿到 URL 立即下载转存，不依赖链接存活。设置页加了协议下拉，两种协议都保留。

**响应解析不死绑字段路径**。用递归查找第一个像图片的 URL 或 base64，而不是写死 `output.choices[0].message.content[0].image`。阿里云的响应字段半年内改过多次，死绑路径会让一次小改动直接打断功能。base64 的判定用魔数（PNG/JPEG/WebP 头）而不是长度阈值——测试时正是长度阈值把小图漏判了。

**流水线顺序纠正**。原设计是「先抠图再生成 Q 版」，实测确认 qwen 的图像编辑**不保证透明背景**（本次生成结果 alpha 最小值就是 255，即完全不透明）。所以改成「原图 → 生成 → 抠图去底」，并让 Q 版链路依赖抠图服务：配了就自动去背景，没配就保留带底色结果并明确提示，不假装成功。抠图失败也不丢弃已计费的结果。

**独立的图像 apiKey**。原来对话和图像共用一个 key 字段，你对话用智谱、图像用百炼时根本填不进去。新增 `imageApiKey`，留空回落到主 key。

**中文提示词**。qwen 对中文的语义遵循明显好于英文，prompt 明确了头身比 1:1.2、保留发型发色服装配饰、纯色背景、无水印。

## 验证

假服务器 8 组用例：OSS URL 下载落盘、base64 落盘、401 提示检查地域、404 提示地址不完整、429 提示限流、额度不足透传原文、无图片明确报错、请求体结构符合百炼规范。

真实接口 4 项：取原图、生成成功、确认结果带底色（符合预期）、抠图后真透明。
